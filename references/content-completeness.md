# 内容完整性：逐字呈现与覆盖率校验

**本技能的第零原则：音频里人物说的内容必须完整呈现在字幕上，与说话人一一对应。排版问题永远用「拆段」解决，严禁用「删内容」解决。**

本文件用 2026-11-04 的实战返工案例（IEM Beijing 2026 Falcons vs FaZe 赛后采访，60 秒）固化这条原则。

## 一、反面教材：压缩版是怎么翻车的

同一素材先后做了两版：

| | ❌ 压缩版（6 条） | ✅ 逐字版（16 条，用户验收通过） |
|---|---|---|
| 长回答 | 压成 1 句摘要 | 按词级时间戳拆成 4 句 |
| 短插语 | 全部丢弃 | 全部找回并成条 |
| 教学长句 | 砍半塞进一行 | 拆成 2 条连续呈现 |
| 结尾欢呼 | 不输出 | 标注「（全场欢呼）」 |

压缩版被用户退回的原话：**"内容不完整，删掉的内容太多了……如果超出的可以写到下一段字幕，而不是直接删掉。"**

### 四种丢失内容的失败模式（以后严禁再犯）

1. **整段压缩成摘要**：把 kyousuke 的四句回答 "some mistakes and how to fix it / i think everyone does mistake in a match / you cannot play without a mistake / so, yeah, of course we did" 压成一句"一些失误以及怎么改正"。**长段必须按句拆分，不是按句合并。**
2. **丢弃短插语**：主持人衔接词 "and that's it."（13s）、"yeah!"（22s）被当成"不重要"删掉。**短句也是说话内容，必须成条**（时间轴用 ASR 原值，哪怕只有 0.4 秒）。
3. **丢弃句首词**：30 秒处的 "yes, and..." 藏在下一段的句首，拆分长段时连同前半句一起丢了。**拆段时检查每个块的起点，上一句的尾巴不许被吞掉。**
4. **欢呼/环境声不做标注**：结尾 7 秒观众欢呼直接空着。**纯环境声可以不翻译，但要有一条「（全场欢呼）」让观众知道这段不是字幕丢了。**

## 二、完整性工作流（必做）

### 1. 转写必须带词级时间戳

`asr_util.py` 默认输出词级时间戳（`words` 字段），**这是拆段的唯一合法依据**——拆分长句时，每个新块的 start/end 必须来自 ASR 词级时间轴原值，不许自己估时间。

```
词级时间戳示例：
"last year you learned more and this year it's so simple: didao"
→ 拆成 14.28-16.06「last year you learned more」
→ 加上 16.06-20.40「and this year it's so simple: didao」
两条文字拼起来 = 原句一字不差
```

### 2. 交付前跑覆盖率审计（强制）

```bash
"$PY" "$SK/scripts/gaps.py" "<音频路径>" "<最终 pairs.json>" --tolerance 1.0 --min-gap 2
```

审计对象是**最终 pairs.json**（不是中间转写稿）。输出的每个「有声音无字幕」区间必须能归入下表之一，否则不许交付：

| 区间性质 | 处置 |
|---|---|
| 人物在说话 | **必须有字幕**，没有就补 |
| 纯静音（probe 的静音区间内） | 跳过，无需处理 |
| 笑声/掌声/欢呼等环境声 | 加一条「（全场欢呼）」之类的标注块 |
| 有声音但重转两次仍识别不出 | 交付说明里列为存疑区间，**不许假装它不存在** |

### 3. 拆分优先级（超宽时的处理顺序）

1. **拆段**（首选）：按词级时间戳在语义边界（从句、逗号、并列成分）切开，内容零损耗；
2. **精简**（兜底）：仅当一个语义单元本身超宽时才用，且删改内容必须在交付说明里逐条列出；
3. **禁止**：删整句、删插语、换行、改时间戳。

## 三、交付前完整性检查清单

- [ ] 对照转写稿逐句核对：每一句说话内容都能在字幕里找到，无一遗漏
- [ ] 短插语（yeah / ok / and that's it 等）全部成条
- [ ] 长句拆分处文字拼接 = 原句完整，无中间丢词
- [ ] 环境声段有标注或已记入交付说明
- [ ] `gaps.py` 对最终 pairs.json 审计零未解释区间
- [ ] `validate_srt.py` 零报错
- [ ] 交付说明包含：条数、覆盖率结论、存疑区间、（如有）精简删改清单

## 四、成功案例存档
