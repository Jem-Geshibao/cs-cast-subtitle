# 双语对照字幕的排版与翻译风格

面向抖音竖屏发布，参考已交付的历史稿件（`assets/example_bilingual.srt`）。

## 一、字幕块结构

```
<序号>
HH:MM:SS,mmm --> HH:MM:SS,mmm
源语言行1（小写）
源语言行2（小写）
目标语言行1
目标语言行2
```

- **源语言段**：先源语言（英文按要求全小写），后中文对照，共 2–4 行。
- **已是目标语言的段**（中文解说、中文采访）：**只输出中文**，不做双语对照，避免画面重复。
- **静音段不输出字幕**。
- **时间轴严禁改动**：必须使用 ASR 原始 start/end，哪怕某条只有 1.2 秒或长达 6 秒。宁可让文本换行，也不要合并或拆分时间块。

## 二、抖音竖屏 6 号字安全值

脚本按「CJK/全角权重 1.9，其他权重 1」估算行宽：

| 内容 | 单行上限 |
|---|---|
| 纯英文（源语言行） | ≈ 46 字符 |
| 纯中文（目标语言行） | ≈ 19 字 |
| 单块总行数 | ≤ 5 行（源 3 + 中 2），建议 4 行以内 |

处理原则：
- 超长先**断句换行**（在逗号、连词处断开），不要硬塞一行。
- 中文行不要为了凑字数乱删信息；可在两行内讲完。
- 校验脚本报超宽时，优先把长句拆成两行，其次精简语气词。

## 三、翻译风格（职业解说口吻）

1. **短句、动词强**：拿下、收下、轰出、撕开、架住、偷掉、打崩、稳拿、冲击。
2. **保留情绪**：`absolutely beautiful from donk` →「donk 这波太漂亮了」；不要译成平铺直叙的书面语。
3. **不要过度意译**：解说信息（人数、方位、道具）必须准确传达，`four back towards CT` 必须译出"四人回防"。
4. **术语与 ID 不翻译**：点位名（jungle、short、connector、banana）、地图名、选手 ID、战队名保留原文。
5. **数字照抄**：比分 `14-0`、比分差、回合数直接保留，不换算、不改写。
6. **标点**：中文行用全角标点（，！？），**行尾不加句号**；源语言行保留原有轻量标点。
7. **中英混排不加空格**：`donk拉开距离`、`只要清掉jungle就行`，历史稿统一如此。
8. **第一人称**：英文解说的 `we / us` 通常指其本国或支持的队伍，必要时译为"他们"。

## 四、一致性检查（交稿前必做）

- [ ] 同一选手 ID 全文写法统一（donk 不一会儿 Donk 一会儿 donk）
- [ ] 同一战队译名统一（TYLOO 一律"天禄"或直接保留 TYLOO）
- [ ] 同一张地图的点位译法统一（jungle 不一会儿"丛林"一会儿 jungle）
- [ ] 存疑项已在交付说明中列出（`【?】`），未混入字幕正文

## 五、交付物命名

- 字幕：`<原名>_bilingual_corrected.srt`
- 中间产物：`<原名>_segments.json`（主转写）、`_fill.json`（补录）、`_recheck.json`（攻坚重转）
- 校验：运行 `validate_srt.py`，通过后才能交付。
